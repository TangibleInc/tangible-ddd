## 1. Method

1. Local clones: every `composer.json` under `/Users/titustc/tgbl` outside `vendor/` and `node_modules/` that mentions `tangible/ddd`. Locks and `vendor/tangible/ddd/tangible-ddd.php` were read only for installed versions.

Code search misses repositories (it did not return `tangible-certificates` or the standalone `wp-rest` repo), so I also listed all 219 TangibleInc repositories pushed since 2025-12-01 (ddd v0.1.0 is dated 2025-12-31 on Packagist). For each one I fetched the root `composer.json` and every nested non-vendor `composer.json` (117 files) through `gh api`, on the default branch.
3. Symbol usage: I shallow-cloned each consumer into the session scratchpad, not into any source tree, and ran a scanner over `.php` files. It picks up `use` statements (grouped ones included), inline `\TangibleDDD\...` references, and namespaced function calls. It also reads `.yaml/.yml/.xml/.neon` for FQCN service IDs, and `extends` / `implements` / trait / attribute clauses. The counts in §4 cover production code only: `tests/`, `vendor/`, `.reference/` and `worktrees/` are excluded. A symbol was checked against 0.6.6 by resolving its PSR-4 file under `ddd-src/`, or its namespaced function under `ddd-wordpress/`.
4. Shipped artefacts: I downloaded the current release zips (cred `latest`, `lms@0.12.0`, `quiz@0.7.0`, certificates `v0.3.1`) and read the bundled `vendor/tangible/ddd/tangible-ddd.php` version and any compiled DI container.

## 3. Conclusions

### 3.1 Real compatibility window

- **Code that runs today spans 0.6.5 to 0.6.6.** Shipped zips bundle 0.6.5 (LMS 0.12.0, quiz 0.7.0, certificates 0.3.1) and 0.6.6 (cred latest). The oldest manifest floor among live consumers is `^0.6.2` (LMS/quiz). Datastream requires 0.6.0 at runtime.
- **The window is 0.6.x, not 0.2.x.** Review finding 1 in `txp/.docs/specs/tangible-ddd-extraction.md:343` reads "0.2 → next" off reporting's `^0.2.5`. The code does not bear that out. Reporting master has no ddd code, and its feature branch already references classes deleted in 0.4.0. Under the newest-wins loader (`tangible-ddd.php:274-290` maps every `TangibleDDD\` class to the *winning* copy's `ddd-src/`), that branch cannot boot next to any live 0.6 consumer. So 0.2 is dead for anything that shares a site with LMS, cred or certificates. Reporting has to be migrated to 0.6, not supported as a 0.2 consumer (F3).
- **Within 0.6.x the extension surface has not moved.** No public or protected method signature changed from v0.6.0 to HEAD in any interface consumers implement (IDDDConfig, IOutboxRepository, IProcessRepository, IBehaviourWorkflowRepository, IOutboxPublisher, ICommandHandler, IQueryHandler, IIntegrationEvent, IAnnouncesIntegration, IRecordsDomainEvents, IEventFromArgs, ISagaBehaviour, IPersistsAggregates, ISearchableRepository, IDomainService, ICommand, IQuery; checked with `git diff v0.6.x HEAD`). None changed from v0.6.5 in the base classes consumers extend either. A few moved between v0.6.0 and v0.6.5: WorkflowHandler, WordPressActionHandler, PersistsAggregatesRepository, SelfHandlingCommand, RaisesEvents. So "0.6.5 contract == 0.6.6 contract" holds, and 0.6.5 is the right freeze point for the conformance fixtures.
- **On a WordPress site the effective contract is the newest copy's contract, bound to the oldest shipped caller's expectations.** Three shipped releases carry compiled containers that call ddd constructors with fixed arity (F5). Any ddd-wp release that wins the loader on a site with LMS 0.12.0 has to keep those constructors callable exactly as compiled.
- **Recommendation:** declare the legacy window as `>=0.6.2 <0.7` for WP consumers, freeze fixtures at 0.6.5, and treat 0.6.6 as the baseline. The extraction ships as `0.7.0` or later of a `tangible/ddd` distribution that keeps the 0.6.5 FQCNs, constructor signatures, procedural functions and loader. The new `ddd-core`, `ddd-wp` and `ddd-symfony` packages sit behind it.

### 3.2 Real PHP floor

- Every live consumer declares `>=8.2` or declares nothing: cred has no `php` entry, but it resolves Symfony 7.4 through ddd. LMS, quiz, certificates and reporting-feature headers say `Requires PHP: 8.2`. CI for LMS, certificates and ddd itself runs 8.2 (`.github/workflows/phpunit.yml:20`).
- The library's `"php": ">=8.1"` (`composer.json:13`, plugin header `tangible-ddd.php:10`) is not satisfiable in practice. `symfony/dependency-injection ^7.4` and `symfony/config ^7.4` (`composer.json:14,18`) lock to 7.4.x, which requires PHP `>=8.2` (`composer.lock`, and symfony/filesystem and var-exporter too).
- Nothing in `ddd-src/` or `ddd-wordpress/` needs 8.2+ syntax. I found no readonly classes, DNF types, typed class constants or `#[Override]`, and the true/false/null standalone-type hits were false positives. The 8.2 floor comes entirely from Symfony 7.4.
- **Real floor: PHP 8.2 for every package that pulls Symfony DI/Config.** ddd-core can honestly claim 8.1 only if Symfony DI is moved out of core (see F9). No consumer runs 8.1: the docker-factory `php8.1` image carries an LMS that itself requires 8.2. I recommend 8.2 across all new packages, with the manifest corrected, and a CI matrix of 8.2 and 8.3 (the local dev toolchain is 8.3.30).

- **lms / quiz.** Heaviest on CQRS: 67 and 27 query handlers, 50 and 37 command handlers. LMS has a Doctrine outbox (F7). Both use Jetpack Autoloader (F13) and ship compiled containers (F5). `quiz` extends `Entity` 18 times.
- **tangible-certificates.** Small (15 files) but shipped with a compiled container. Uses `RecordsDomainEvents`/`IRecordsDomainEvents`, which no other consumer uses.
- **tangible-datastream.** The only user of `SelfHandlingCommand`/`SelfHandlingQuery`, `SelfExecutingCommandMiddleware`, `IOutboxPublisher` decoration around `ActionSchedulerOutboxPublisher`, `integration_action`/`infrastructure_action`, `OutboxDeadLettered`, `DDDCompilerPasses`, and the `Tangible_DDD_Versions` API. It is the reference consumer for `.reference/` in ddd itself (`composer.json` `ref:datastream` script).
- **tangible-reporting.** See F3. It uses `WordPressRepository`, `WPErrorException` and `DDDConfig`, which no one else uses.
- **wp-rest.** See F14.

## Open questions

1. **tangible-reporting:** is `feature/tangible-ddd` (123 commits, no PR, `^0.2.5`, pre-0.4 API) still going to ship? If so, who re-targets it to `^0.6`? Answering this closes review finding 1 either way.
